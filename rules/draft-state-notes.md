# Notes — draft-state

Reasoning for `rules/draft-state.md`. Deliberately *not* bundled into
each skill: a copy of this per consumer would be design history with no reader,
and the audience for it is a person editing the rule, who has this checkout.

Moved here with the rule itself, from `backlog-orchestrator/NOTES.md`, *Draft state*, when the rule was split out so that `settle-and-merge` and `implement-issue` could cite it without pointing into `backlog-orchestrator` (#138). "The run" and "the per-PR block" in these entries are that skill's run and its record of the PR, as they stood when the entry was written.

**Why this is a shared rule (#138):** three skills apply it — `backlog-orchestrator` and `implement-issue` promote, or decline to, under it, and `settle-and-merge`'s gate excludes the drafts it defines as held. While it lived in `backlog-orchestrator`, the other two pointed up into an orchestrator neither runs under for a definition the gate needs on every evaluation. What stayed in `backlog-orchestrator` is what only it does: recording the convention at adoption against its per-PR block, the repair worker's hands-off rule, and the review trigger comment's independence from promotion.

**Why promoting requires the forge timeline, not the block (round 2):** the held-draft read was timed "before applying the gate", and promotion moved to every supervision cycle — so it would resolve held-ness from the per-PR block, which invariant 1 calls a cache and which the gate's own rule says cannot answer this question after a restart. The cost is not a wasted promotion: the discriminator is *currently a draft and ever ready*, so promoting a withdrawn PR erases the only evidence it was withdrawn, permanently, and the gate then merges it. Hence the timeline read as a precondition of any draft-state change, and held-ness sticky once observed.

**Why the three-state reference is scoped (round 2):** those states are written as merge decisions and one of them ends "publish and merge". Imported whole into a supervision cycle it hands a run an instruction to merge with no gate evaluated and no summary to evaluate it from. The convention publish takes the classification and the un-settle, and nothing else.

**Why the convention is read at first preflight, recorded against the PR at adoption, and evaluated each cycle (round 1, Sept 2026):** the first version said what to do with a promotion convention and never said when the run looks or where the answer lives — so the rule was inert, or worse, re-derived at an arbitrary moment, which makes the same PR merge or not depending on when the run happened to glance. Adoption is where the run already records a PR's head, base and trigger state; the supervision cycle is where it already re-reads CI, review and threads, so a PR that becomes eligible mid-run is promoted when it becomes eligible. It is recorded per repository, beside the publish-triggers observation, because it is a fact about a repository rather than about a PR — `create-pr` reports only what decided the as-created state, so there was no chain to inherit it from.

**Why the repository's convention wins (Sept 2026):** the skill said the run does not promote drafts; two repositories' `CLAUDE.md` said to mark a PR ready once CI is green, the review is back and every actionable finding is resolved. Not a tension — a contradiction, with no tiebreak anywhere in the precedence machinery, which resolves budgets and merge policy from `.claude/agent-policy.json` and says nothing about prose conventions. A run reading both promoted one PR and left three in draft, and was right either way.

The resolution is not a weakening of the social-act reasoning but an application of it: that reasoning says a *person* decides when another person is asked to review, and a documented convention is the person deciding, in advance, in writing, with the conditions attached. What the run must not do is decide from a heuristic that a PR "looks done" — which is why the deleted promote-on-clean-review behaviour stays deleted and this is not a policy knob. The conditions are the convention's own, deliberately, so the run cannot broaden them.

Two guards come with it. The ready-to-draft direction stays closed in every case, because withdrawing a PR from review is a decision about someone's attention and no convention has been observed to ask for it — and because the held-draft discriminator reads exactly that direction. And a promotion under a convention is a publish like any other, so it takes the three-state rule rather than being treated as inert.
