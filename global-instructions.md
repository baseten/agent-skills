- When you name a tracker issue, make it a link to the issue, never a bare identifier such as `ENG-123`. That holds in a chat reply as much as in a PR, comment or message you write. Use the URL the tracker returned, or its canonical issue URL. A PR or issue named outside its own repository is a link too, since `#123` auto-links only there.
- When choosing the skill to start a task with, where an available skill declares that it extends another — `metadata.extends` in its frontmatter, or its description saying so — use it rather than the one it extends. It holds the settings and invokes that skill itself.
- A skill named by its bare name, such as `create-pr`, is the same skill as one listed with a plugin prefix, such as `agent-skills:create-pr`.
- When moving a project to a new Node or pnpm version, or changing how its Claude Code cloud environment installs them, follow the *Node and pnpm upgrades* rule, `references/node-and-pnpm-upgrades.md` in the `upgrade-npm-dependency` skill's directory. In that move, never install pnpm through Corepack.
